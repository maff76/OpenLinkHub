OpenLinkHub v12.4.74z7d9r — iCUE effect UI audit pass 1

Scope: UI only. No renderer, playback, profile activation, parser, or hardware behaviour changes.

Changed file:
- static/js/icue-profiles.js

Confirmed from supplied Cobalt profile + iCUE screenshot:
- Wave duration is stored as milliseconds (3000) but iCUE displays seconds (3.0).
- Wave velocity is stored in tenths of lights/sec (500) but iCUE displays 50.0 lights/sec.
- Wave tail is stored in tenths of lights (100) but iCUE displays 10.0 lights.
- Two Sides and Angle already map directly.
- Therefore the Cobalt Wave values were not the wrong layer in this example; the editor was displaying raw serialized units instead of iCUE display units.

Transition graph correction:
- Horizontal coordinate remains authored transition time/position.
- Vertical coordinate now reads alpha from authored #AARRGGBB transition colours and converts it to 0–100%.
- This matches the observed iCUE graph behaviour where dragging a point vertically shows 0–100%.
- Explicit opacity leaves remain supported.

Wave/Ripple friendly display:
- Lighting time: raw ms -> seconds.
- Velocity: raw value / 10 -> lights/sec.
- Tail: raw value / 10 -> lights.
- Raw authored values remain unchanged and remain visible in source diagnostics.

Effect structure audit from supplied profiles:
- StaticLighting: transition/static colour + opacity.
- RainLighting: first/second colours, random, opacity, speed, direction.
- WaveLighting: transition graph, duration, velocity, tailLength, isDoublesided, angle.
- RippleLighting: transition graph, duration, velocity, tailLength; some profiles also carry trigger/play semantics and additional fields.
- ColorWaveLighting: first/second colours, random, speed, direction.
- ColorShiftLighting: first/second colours, random, speed.
- ColorPulseLighting: first/second colours, random, speed.
- VisorLighting: first/second colours, random, speed, direction.
- InfinityLighting: first/second colours, speed, direction.
- GradientLighting: transition graph; authored stops carry colour and alpha.
- WaterColorLighting: first/second colours + speed in observed profiles.
- RainbowWaveLighting: speed + direction.
- SpiralRainbowLighting: speed (direction only where actually authored).
- RainbowLighting: speed in observed Master Chief profile.
- BlinkLighting/BreatheLighting: observed, but supplied profiles do not yet give enough modern iCUE UI evidence to invent additional friendly controls.

Still deliberately not guessed:
- Meaning/display scaling of effect-specific fields not confirmed by screenshots/profile pairs.
- Rain direction numeric semantics.
- Ripple special trigger/play-option presentation.
- Effects not represented by supplied modern profile/screenshot evidence (for example Marquee/Sequential/Rotary Stack) retain generic authored-value exposure until captured.
